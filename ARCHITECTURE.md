# 🏛️ Sentinel Architecture Specification

> **System:** Sentinel — Self-Verifying Autonomous Agent on Cloudflare  
> **Target Platform:** Cloudflare Workers, Durable Objects, Workflows, Agents SDK  
> **Language & Framework:** Python 3.9+, FastAPI, Pydantic v2

---

## 1. System Overview & Core Invariants

Sentinel is designed around four non-negotiable architectural invariants:

1. **Rule 1 (The Grounding Invariant):** An important claim cannot transition to `VERIFIED` without at least one primary documentation citation linking to an authoritative source and matching excerpt.
2. **Deterministic Confidence Invariant:** Confidence is never generated by LLM self-assessment; it is computed via a fixed 4-factor formula:
   $$\text{Confidence} = 0.35 E + 0.30 A + 0.20 V + 0.15 X$$
3. **The Codex Policy Invariant:** No mutating external tool side effect (`create_issue`, `update_file`, `deploy`) may execute without explicit cryptographic or operator approval.
4. **The Closed-Loop Invariant:** An action is never assumed successful upon tool return; postconditions must inspect live target state directly.

## 3. The Bipartite Evidence Graph

Sentinel models knowledge as a bipartite directed graph $G = (C \cup E, \mathcal{E})$ where:
- $C = \{c_1, c_2, \dots, c_n\}$ is the set of **Claims** extracted from research subtasks.
- $E = \{e_1, e_2, \dots, e_m\}$ is the set of **Evidence Nodes** containing verifiable quotes, source URLs, and timestamps.
- An edge $(c_i, e_j) \in \mathcal{E}$ indicates that evidence $e_j$ grounds claim $c_i$.

### Verification Rule:
A claim $c_i$ achieves `ClaimStatus.VERIFIED` if and only if:
1. $|\{e_j : (c_i, e_j) \in \mathcal{E}\}| \ge 1$ (for medium importance) or $\ge 2$ (for high importance).
2. The citation URL is valid and grounded in the Cloudflare developer documentation domain.
3. No active, unresolved `Conflict` references $c_i$.

## 4. Cloudflare Durable Objects & Workflows Integration

### Durable Object State Isolation
In a Cloudflare production deployment, every `Mission` is mapped to an isolated **Durable Object** instance indexed by `mission.id`:
- Guarantees strict sequential ordering of state mutations.
- Eliminates race conditions during parallel subtask completion.
- Provides transactional WebSocket connection multiplexing.

### Cloudflare Workflows for Resilient Execution
Mission phases are implemented as idempotent workflow steps:
```typescript
export class MissionWorkflow extends WorkflowEntrypoint<Env, Params> {
  async run(event: WorkflowEvent<Params>, step: WorkflowStep) {
    const plan = await step.do("decompose-objective", async () => { ... });
    
    const [resA, resB, resC] = await Promise.all([
      step.do("research-a", async () => { ... }),
      step.do("research-b", async () => { ... }),
      step.do("research-c", async () => { ... }),
    ]);

    const verification = await step.do("verify-claims", async () => { ... });

    if (verification.conflicts.length > 0) {
      await step.do("targeted-resolution", async () => { ... });
    }

    if (action.requires_approval) {
      // Workflow sleeps durably until external webhook/approval is triggered
      await step.waitForEvent("operator-approval", { timeout: "7 days" });
    }

    await step.do("execute-postconditions", async () => { ... });
  }
}
```

### Transient Fault Recovery
When an external tool returns `HTTP 503 Service Unavailable`, the workflow step automatically triggers exponential backoff:
$$T_{\text{wait}} = \text{base\_delay} \cdot 2^{\text{retry\_count}} + \text{jitter}$$
State is preserved without restarting the upstream research agents.

## 5. Closed-Loop Postcondition Verification

Unlike naive agents that treat an API 200 OK as a proxy for success, Sentinel executes a deterministic follow-up query:

```python
# Action: create_issue(title="ADR: Edge Caching Architecture")
# Expected Postcondition: Issue must exist in repository with exact title

actual_issue = await github_tool.get_issue(repo, issue_number)
if actual_issue and actual_issue["title"] == expected_title:
    action.postcondition_verified = True
else:
    action.postcondition_verified = False
    raise PostconditionFailure("Live state does not match expected postcondition")
```

This guarantees zero silent partial failures across automated deployments.
